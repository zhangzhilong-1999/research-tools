# 通过 ai 定时任务， 实现科研文章自动化推送

## 一、核心目标

通过**豆包云电脑定时任务**实现全自动化：

1. 每周定时检索控制与优化领域的最新学术文献；
2. 精简摘要通过企业微信推送到个人微信，微信内可直接查看；
3. 完整Markdown格式的详细文献报告自动提交到GitHub仓库归档，历史报告永久留存，可通过链接查看完整表格、摘要、DOI等信息。

---

## 二、前置准备1：GitHub 侧（用于存放完整文献报告）

### 准备步骤

1. 注册并登录 GitHub 个人账号；
2. 创建**公开仓库**，命名为 `literature-weekly-report`，仓库内新建 `reports/` 文件夹用于存放所有周报文件；
3. 生成**细粒度 PAT（Personal Access Token）**，作为豆包调用 GitHub API 的凭证。
   - 仓库范围 | **仅选中 `literature-weekly-report` 这一个仓库**
   - 仓库权限 | 仅开启 `Contents: Read and write` 

### 权限设置与原因

| 配置项 | 设置要求 | 设置原因 |
| --- | --- | --- |
| Token类型 | Fine-grained 细粒度令牌（禁止用经典 Classic PAT） | 经典 PAT 的 `repo` 权限会开放你全部仓库，泄露风险极大；细粒度可以限定到单个仓库，最小权限原则 |
| 仓库范围 | **仅选中 `literature-weekly-report` 这一个仓库** | 即使 token 泄露，攻击者也只能操作这一个仓库的文件，无法访问你的其他仓库、账号信息、个人设置 |
| 仓库权限 | 仅开启 `Contents: Read and write` | 只满足「新增/修改Markdown文件」的最小需求，Issues、Workflow、部署等其他权限全部关闭，进一步收缩风险边界 |
| 过期时间 | 推荐设置90天自动过期 | 就算 token 泄露，也有失效时间上限，降低长期风险 |

> 
> 补充：仓库设为公开，是为了微信内点击链接时无需登录 GitHub 即可直接查看文档内容。

---

## 三、前置准备2：企业微信侧（作为推送中介，实现消息到微信）

### 准备步骤

1. 下载企业微信APP，用个人微信扫码**创建个人企业**：无需营业执照、无需资质，填写企业名称即可创建，单人使用完全满足需求；
2. 在企业内创建一个群（默认全员群即可），进入群设置 → 群机器人 → 添加机器人，自定义机器人名称；
3. 获取机器人的**Webhook 完整地址（含 key 参数）**，格式为 `[https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx](https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx)`，这是推送消息的唯一凭证；
4. 个人微信绑定/关注该企业 (用个人微信扫描 ”企业微信网页版-我的企业-微信插件-邀请关注“ 的二维码)，确保企业微信的消息通知能同步到微信APP。

## 四、定时任务组装与完整执行流程

把上述 GitHub 凭证、企微 Webhook 地址填入定时任务指令后，完整自动执行流程如下：

1. **定时触发**：每周一 05:00（北京时间）任务自动启动，记录并输出任务开始时间。
2. **文献检索**：
   - 按附录1的关键词、附录2的数据源，检索近一周新发表文献；
   - 检索校验重复至少3次，交叉去重，确保结果准确；
   - 输出两份内容：① 符合附录3格式的精简摘要（用于企微推送）；② 完整Markdown报告（含表格、作者、摘要、DOI等）。
3. **生成文件**：
   - 带日期的归档文件：`reports/weekly-report-YYYY-MM-DD.md`（永久存档，不覆盖历史）
   - 最新文件：`reports/latest.md`（每次覆盖更新，永远指向最新一期）
   - 两份文件开头均包含任务开始时间、结束时间、总用时。
4. **上传 GitHub**：
   - 先新增带日期的归档文件（新建文件不需要 sha 参数）；
   - 再更新 `latest.md`：先GET获取文件sha值，再PUT覆盖更新；若文件不存在则直接新建。
5. **组装推送消息**：严格按照附录3格式组装文本，包含时间统计、文献标题列表、简要详情、GitHub 完整报告链接。
6. **推送微信**：调用企微群机器人 Webhook，发送 text 类型消息，微信端直接收到通知。
7. **任务收尾**：输出任务结束时间、总用时；内置异常处理规则，上传失败时终止推送、latest更新失败时降级使用归档链接。
