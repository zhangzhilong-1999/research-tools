# 步骤

## 步骤0：全量检索执行纪律（最高优先级硬约束，与后续步骤冲突时以本条为准）
(1) 全量展开原则：附录1 中的【每一个英文关键词】与【每一个中文关键词】都必须作为独立检索词逐词执行；严禁按大类合并、严禁只选代表性关键词代替整族、严禁以"已覆盖同类"为由跳过。结束时须声明实际执行的独立关键词总数（≥ 附录1关键词总数 + 补充关键词数）。
(2) 全量来源原则：附录2 中的【每一个期刊、每一个会议、每一个网站/机构/数据库】都必须被单独检索，严禁只检索出版社级代表源。每个来源至少采用一种定向方式：site: 域名限定检索；或直接抓取该刊/该会的"最新在刊 / Early Access / 最新卷期目录 / 在投列表"页面；或在该平台内检索窗口内关键词。
(3) 检索矩阵：必须显式构建并产出"关键词 × 来源"检索矩阵（行=关键词，列=来源），每格填：✅已执行·命中 / ✅已执行·无命中 / ⬜未执行。矩阵为强制交付物，出现任何 ⬜ 即视为任务未完成，禁止进入后续上传与推送。
(4) 逐项打勾：全部关键词与全部来源必须用清单逐项打勾核销（每项标记 completed/in_progress），禁止整体一句带过。
(5) 可追溯：为每一次检索记录 query（含中文/英文）与目标来源；命中条目必须附权威链接或 DOI 以便复查。

## 步骤1：全量文献检索（逐关键词 × 逐来源）
- 检索窗口：{检索时间窗口}，检索此时间区间内新发表文献。
- 检索关键词：见 **附录1**（全部英文 + 中文 + 补充关键词，逐词执行）。
- 数据源：见 **附录2**（逐刊、逐会、逐网站/机构检索）。
- 执行要求：
  1.1 构造关键词全集：附录1 全部英文关键词（逐条、不合并）+ 全部中文关键词 + 补充关键词，共 N 个。
  1.2 构造来源全集：附录2 全部期刊（逐刊）、会议（逐会）、网站/机构/数据库（逐个），共 M 个。
  1.3 执行"关键词×来源"检索矩阵，逐格检索，禁止聚合跳过。
  1.4 逐源定向核验：IEEE Xplore 查 Early Access、ScienceDirect 查 Articles in Press、Wiley 查 Early View、SIAM/Springer 查最新卷期、arXiv 按分类查本周、会议查最新论文集。
  1.5 收集并核验命中文献：从权威来源页确认标题/作者/日期/DOI/摘要；摘要翻译为中文；取不到摘要标注【未获取到原文摘要】；作者单位未标注写"作者单位未在来源标注"；严禁编造。
  1.6 交叉核验：检索与核验全过程重复至少 3 轮，去重、剔除误检。
  1.7 产出两张表：① 检索矩阵；② 逐源审计表（来源｜检索方式｜是否窗口内有条目｜命中条目或"无"）。
  1.8 结束声明：任务结束时逐项声明"关键词 N 个全部检索完成、来源 M 个全部检索完成、命中并核验文献 K 篇"；任何一项未完成即不得宣称任务完成。
- 输出两份内容：
    - 精简摘要文本：即企微推送消息内容，要求见 **附录3**。
    - 完整Markdown文档：文档开头先写明「任务开始时间、任务结束时间、总用时」，正文包含表格，字段：序号、标题、作者+作者单位、文章关键词、期刊、发布日期、DOI链接、摘要。
- 摘要要求：一定要尽力找，并把找到的原文翻译呈现；直接来源页面找不到摘要时，可跳出该网页，通过搜索引擎检索标题/作者尽力获取摘要；确实找不到的，在摘要列标注【未获取到原文摘要】，禁止编造。
- 准确性要求：所有内容要确认属实，禁止胡编乱造；将本步骤的检索与校验过程重复至少3次，交叉核验结果，去重并剔除误检文献，确保结果准确。

## 步骤2：生成文件名与文档头
取当前日期（格式 YYYY-MM-DD），生成两个文件路径：
- 本期日期文件：reports/weekly-report-{YYYY-MM-DD}.md（新增，永久存档，不覆盖历史）
- 最新文件：reports/latest.md（每次覆盖更新，永远指向最新一期）
> 说明：GitHub 仓库中的两份 Markdown 文件，开头均包含任务开始时间、任务结束时间、任务总用时。

## 步骤3：调用GitHub API，先新增日期文件，再更新latest.md
### 3.1 新增本期日期文件（新建，不需要sha）
PUT https://api.github.com/repos/{GitHub用户名}/{仓库名}/contents/reports/weekly-report-{YYYY-MM-DD}.md
请求头：
Authorization: token {GitHub PAT}
Accept: application/vnd.github+json
请求体：
{
    "message": "添加新一周文献周报 {YYYY-MM-DD}",
    "content": "【完整Markdown内容，先转UTF-8，再做标准RFC4648 Base64编码】",
    "branch": "main"
}
说明：新建文件不需要传入sha参数，只有覆盖文件才需要sha；新建会直接追加文件，旧文件全部保留。
> 冲突处理：若该日期文件已存在于仓库（GET 返回 200 且带 sha），则改为携带 sha 的覆盖更新，消息改为"更新文献周报 {YYYY-MM-DD}"。
### 3.2 更新 latest.md（覆盖，必须先取sha）
先 GET https://api.github.com/repos/{GitHub用户名}/{仓库名}/contents/reports/latest.md
请求头与3.1完全一致（Authorization + Accept），从返回结果中读取现有文件的 sha 值。
再 PUT https://api.github.com/repos/{GitHub用户名}/{仓库名}/contents/reports/latest.md
请求头：同上
请求体（文件已存在时，带sha）：
{
    "message": "更新latest为 {YYYY-MM-DD} 周报",
    "content": "【与3.1相同的完整Markdown内容，Base64编码】",
    "sha": "【上一步GET取到的latest.md现有sha】",
    "branch": "main"
}
若 latest.md 首次不存在（GET返回404），则按3.1的新建方式直接创建，不带sha字段。

## 异常处理规则
1. 步骤1检索无文献（文献数量=0）：仍然生成Markdown报告，继续执行后续GitHub上传与企微推送。
2. 步骤3.1 日期归档文件上传失败：终止后续所有步骤，不再更新latest.md，不再执行企微消息推送。
3. 步骤3.2 latest.md更新失败：日期归档文件已成功保存，企微消息链接替换为本期归档链接，继续执行企微推送。
4. 所有HTTP请求设置超时时间30秒，防止任务卡死。
5. 步骤0/1.7 若检索矩阵存在"未执行"格、或缺少逐源审计表、或结束声明未通过，按异常处理：不得进入上传与推送，并在对话框明确报告未覆盖项。
